# Devices

## Supported

Each row is one integration. The spec id is also the Cargo feature that builds
it in, and the vendor group builds in every integration from that vendor (see
[Using it](README.md#using-it)).

**Native** integrations are written in Rust, because their protocols need
handshakes, sessions or binary framing. The others are run from their YAML
spec alone. **Verification** is explained in
[README.md](README.md#verification).

The table is generated by `python tools/devices_table.py`.

## Roadmap

Devices we plan to support, grouped by type. The protocol column is what we
expect to use; it is confirmed when the integration is written.
Documentation is:

- **Public**: the manufacturer publishes the protocol.
- **On request**: the manufacturer supplies it on request or through a partner
  programme.
- **Community**: no manufacturer document, but open implementations describe it.
- **Reverse-engineered**: little public information.
- **Closed** or **Unknown**: no known control path yet.

Help with any of these is welcome, especially documentation and access to
hardware. See [CONTRIBUTING.md](CONTRIBUTING.md).
